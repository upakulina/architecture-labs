# Проектирование архитектуры
Лабораторные работы по дисциплине "Проектирование архитектуры программных систем" (студент: Пакулина У.Л., группа: РИС-22-3)

# Постановка задачи (согласно ВКР)
Крупный университет хочет заменить разрознённые методы ведения рабочих ведомостей (Excel-таблицы, облачные документы, рассылки по почте и в мессенджерах) единой веб-системой с серверной частью и централизованной базой данных. Система должна поддерживать несколько образовательных программ, курсов и семестров и работать как единая точка для ведения оценок и посещаемости.

## Пользователи
Пользователями системы будут сотни преподавателей, несколько тысяч студентов, десятки сотрудников учебного офиса и администраторов системы.

## Требования
- преподаватели просматривают список дисциплин, которые они ведут, и выбирают группу/подгруппу для заполнения рабочей ведомости
- преподаватели задают формулу оценивания по каждой дисциплине (набор элементов контроля с весами), могут изменять её до момента закрытия ведомости
- преподаватели заполняют рабочие ведомости: вводят оценки по элементам контроля и отмечают посещаемость студентов
- система автоматически вычисляет накопленную и итоговую оценку по дисциплине на основе заданной формулы оценивания
- студенты в личном кабинете просматривают рабочие ведомости по своим дисциплинам в режиме реального времени: текущие оценки, итоговую предварительную оценку, формулу оценивания и статистику посещаемости
- студенты видят процент посещаемости по каждой дисциплине и могут анализировать риски недопуска/неудовлетворительной оценки
- сотрудники учебного офиса просматривают итоговые ведомости по дисциплинам, группам, образовательным программам и отдельным студентам
- сотрудники учебного офиса формируют списки студентов, подлежащих пересдаче, и выгружают итоговые ведомости и отчёты в формате .xlsx
- система поддерживает фильтрацию и поиск по программам, курсам, дисциплинам, группам, подгруппам и статусу ведомости (открыта/закрыта)
- все действия с оценками и посещаемостью логируются: кто, когда и какое значение изменил, с возможностью последующей проверки
- реализована ролевая модель доступа (преподаватель, студент, сотрудник учебного офиса, администратор), исключающая просмотр чужих данных и несанкционированное редактирование
- веб-интерфейс и REST/JSON API к серверной части позволяют в дальнейшем подключить мобильные и внешние системы
- интеграция с существующей инфраструктурой вуза: единая аутентификация (SSO) и, при необходимости, обмен данными с LMS/расписанием
- обеспечение требований по защите персональных данных (аутентификация, авторизация, шифрование соединения, резервное копирование данных)
- система предоставляет отчёты и визуальную статистику по успеваемости и посещаемости по выбранной дисциплине, группе, программе и периоду (семестр/год) для сотрудников учебного офиса и администраторов
  
## Дополнительный контекст
- ранее в университете уже разрабатывался настольный прототип системы ведения ведомостей на базе Windows Forms и PostgreSQL; теперь требуется спроектировать архитектуру веб-версии с серверной частью и API на основе накопленного опыта
- опросы преподавателей показали потребность в автоматическом расчёте итоговых оценок, сокращении времени на рассылку ведомостей и возможности экспорта данных в удобном формате
- опросы студентов показали запрос на единый формат отображения оценок, прозрачные формулы оценивания и просмотр статистики посещаемости
- сотрудникам учебного офиса необходимы удобные инструменты для работы с итоговыми ведомостями при отчислениях, пересдачах и мониторинге успеваемости
- университет планирует в дальнейшем интегрировать систему с другими внутренними сервисами и использовать её как часть более широкой цифровой экосистемы для управления учебным процессом
